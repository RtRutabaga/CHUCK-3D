## Conflicts and open decisions for the user

1. **Division of labour (biggest difference).** The notes assign Claude the parkour/traversal controller, camera, animation logic and making integrated assets look right, and Codex the utilities, import/conversion, editor tools, save/load, tests and isolated fixes. The current setup is roughly the reverse. Claude owns character source art, rig and clips; Codex owns movement/runtime and the AnimBP/contact migration now in progress (`docs/AGENT-WORKFLOW.md`, `docs/RIG-CONTRACT-V1.md`).
   - *Suggestion:* don't swap mid-task. Let Codex finish the v1 AnimBP/contact migration it has started. After that, the notes' split would fit well: Claude on the parkour controller/camera/animation feel (open-ended, multi-file) and Codex on import tooling, validators, save/load and tests (it has already built `Import-ChuckV1.ps1` and the validators). This needs the user's decision and an update to `AGENT-WORKFLOW.md`'s ownership table.
2. **"AI should not generate final 3D models, textures or fur by itself."** Chuck's current body, jacket, textures and groom are procedurally generated by Claude-authored Blender scripts. The notes advise sourcing final art from libraries or image-to-3D tools, then Blender cleanup.
   - *Suggestion:* treat v1 as the **rig/animation-ready production placeholder**. Its skeleton, clips, weights, UV layout, sockets and contact data are reusable whatever mesh replaces it. Decide separately whether to pursue a sourced/sculpted hero mesh later.
   - *Constraints:* on this PC's 8 GB GPU, TRELLIS needs 16 GB and Hunyuan3D-2 textured output needs 16 GB (see `RESOURCE-GUIDE-NOTES.md`), so image-to-3D needs a cloud service or low-memory variant. A cloud service is a new dependency or cost, which needs the user's approval.
3. **Always a lit cigarette in his mouth.** PROJECT-BRIEF lists "one cigarette pickup" as a later prototype goal, which implies he doesn't start with one; AGENTS.md lists mouth-held smoking as an eventual rig requirement.
   - *Decision needed:* always-on cigarette with smoke wisp, or picked up in play? The rig supports either.
4. **Scope.** The notes describe the full game: about one hour of play, Twilight-Princess-scale areas, parkour as the signature mechanic, ported dialogue, two lootable items. Their prototype milestone is a harbor slice with parkour (run, jump, climb crates, vault, ledge grab, tail motion), a small-character camera, one NPC dialogue and one lootable item. AGENTS.md and PROJECT-BRIEF currently limit the prototype to one small docks area, character-first, with dialogue and pickups deferred and world work paused.
   - *Reading:* the notes' milestone is a sensible **next** target once Chuck's character and walking are signed off. It shouldn't be started before the current v1 runtime migration verifies.
   - *Consistent either way:* Chuck himself never speaks. NPC speech only; this matches both documents.
5. **Colour wording.** The notes say "brown rat"; AGENTS.md says "gray rat"; the reference images show grey-brown. Current art follows the reference images, which should stay the tiebreaker.
6. **Retargeted mocap and Control Rig tail.** The notes suggest human mocap retargeted with the IK Retargeter and Control Rig or physics for the tail. The current v1 clips are authored procedurally, and RIG-CONTRACT-V1 chose Two Bone IK without Control Rig for the first migration.
   - *Suggestion:* evaluate retargeted Game Animation Sample traversal clips when parkour starts, since vault, mantle and ledge grab are hard to author procedurally. Add Control Rig or physics tail when the parkour work needs it. Each is an engine plugin/content decision to record first.
7. **Jacket as separate mesh with Chaos cloth.** The jacket is currently a separate shell within the one skinned mesh, with graded weights and no cloth simulation. Splitting it into its own cloth-simulated mesh is feasible later; it would add GPU/CPU cost on this PC. It should follow the groom performance check, not run concurrently.
